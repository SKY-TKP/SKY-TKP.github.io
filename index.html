One Ranking Engine

A single engine powers every creator choice: weekly AI drafts, recommendations and the shortlist picker. It filters by brand rules, scores 7 weighted factors (content fit, tone, engagement rate, brand signature, history, language, trend), then re-ranks for agency caps and Thai-content share.

Workflow Automation • Conversational AI

LINE Sales Assistant · AI Chat Commerce on n8n

Oct 2026

Upgraded an AI sales assistant on LINE for a perfume brand so every chat moves toward a purchase: it answers product questions, recommends scents and closes the sale with a checkout link. Built on n8n, Google Sheets and Google Gemini, validated in simulation and prepared for live UAT.

96n8n workflow nodes
80+Simulated chats, 0 errors
60 / 60FAQ answers validated

⚡ How it flows

  1. 💬 Customer message
  2. 🛡️ Guards
  3. 🧠 Rules first, AI if needed
  4. 📚 FAQ + live stock
  5. 🔗 Reply + checkout link

Checkout Inside the Chat

Fixed a buying loop where the bot repeated the same scent description. The new flow guides scent → size → quantity → a product link with the chosen size pre-selected, and 34 FAQ answers were rewritten to end with one question that moves the chat forward.

Live Stock Awareness

Added 2 nodes that read the store's public product feed on each message (~0.7 s). Sold-out sizes are named plainly and similar in-stock scents are offered, with a 3-second timeout fallback and all 24 size links verified.

Rules First, AI Second

Deterministic rules handle most messages; Gemini only reads taste and intent when rules can't, and never writes the reply. Guardrails enforce owner-approved prices and no fake urgency, and every copy change must pass the bot's own validator.

Safe Delivery

All work was done on a clone of the workflow with 12 backups. Changes were verified by the FAQ compiler (60/60 pass), 80+ simulated chats running the real workflow code, and 58 prepared UAT cases.

🧭 System Design

VIBES LAB Music Director

How a brand book becomes the music playing in a shop: one system for the client app and the Director's studio.

🗺️ End-to-end flow

01 · Inputs

  • 📘 Brand bookThe client's PDF: identity, tone, audience
  • 🎵 Track libraryTrack profiles: BPM, energy 1–5, mood tags, language
  • 💬 Client feedbackLike · not this song · request a change

02 · AI + Engine

  • 🧠 LLM as translatorBrief → targets: energy by daypart, BPM, Thai share, moods
  • ⚙️ Recommendation engineFilter → score 7 factors → rerank
  • 🗓️ Weekly draftDay types × 1–2 hour playlists

03 · Director Studio

  • 📝 Draft → ✅ Review → 🚀 PublishEdits to a published week need re-approval
  • 📥 QueueRequests, reviews and offline players in one list
  • 📊 ReportsPlay log, likes and royalties by label

04 · Client App

  • ▶️ TodayNow playing + Pool mood: Normal · Softer · Livelier
  • 🗓️ Weekly scheduleExport to PDF or Excel
  • 🔊 Shop speakersPlays on the shop's own sound system

↺ Feedback loop: likes and "not this song" flow back into the engine's history score, so next week's draft fits better.

⚙️ Inside the recommendation engine

  1. 1TargetFrom the slot, the client's brief and the weather
  2. 2FilterBanned tags, explicit lyrics, songs the Director rejected
  3. 3Score7 parts, each 0–1, weighted mean
  4. 4Rerank≤ 2 songs per artist, no back-to-back, Thai share

Scoring weights

Mood×3
Energy×2
BPM×2
Scent×2
History×2
Language×1
Trend×1

📐 Design principles

🎯One engine for every pick

AI drafts, recommendations and the playlist builder all call the same scoring engine.

🗣️LLMs translate, never pick

Language models turn briefs into targets; they never name tracks or see the catalogue.

🎛️Clients listen, the Director decides

Nothing AI-drafted reaches a client without the Director's approval.

🔒Collect only what's needed

Multi-tenant PostgreSQL with Row Level Security, role-based access and PDPA-minded data.
